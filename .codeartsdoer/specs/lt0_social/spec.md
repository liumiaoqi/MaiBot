# LT-0: 社会关系动态化

## 背景

MaiBot 最大的架构缺陷：社会关系是僵化的。人物画像和关系数据来自配置文件，运行时几乎不变。智能体无法主动建立、修改、深化与用户/其他智能体的关系。

人类记忆的本质：一个人怎么分类事物，取决于他的社会关系。分类从关系中涌现，不从文本中推断。社会关系僵化 → 记忆无法涌现 → 分类只能靠规则 → 情绪无法影响关系 → 欲望系统空转。

## 需求

### SOC-1: 关系强度连续化

**当前**：关系是二元存在（有/无），配置文件写死。
**目标**：每条关系有连续 `strength`（0.0~1.0），随交互动态演化。

**演化规则**：
- 每次交互（对话/提及/共同活动）：strength += 0.02（上限 1.0）
- 矛盾事件（拒绝/冲突）：strength -= 0.05（下限 0.0）
- 时间衰减：strength *= 0.999^(hours_since_last_interaction)
- 情感加权：正面情绪交互 ×1.2，负面 ×0.8

**存储**：关系强度存入 A_memorix RelationStore（与现有 relations 表复用，新增 strength 列）。

### SOC-2: 关系标签涌现

**当前**：关系标签（"朋友""同好"等）来自配置。
**目标**：关系标签从交互模式中涌现。

**涌现机制**：
- 统计交互话题分布 → 高频话题成为关系标签（如总聊音乐→"音乐同好"）
- 统计交互时间模式 → "深夜谈心""日常闲聊"等标签
- 标签有强度（0.0~1.0），低强度标签自动淘汰
- 标签可被新交互强化或弱化

### SOC-3: 关系影响感知权重

**当前**：管家三层过滤的权重来自配置（规则过滤的"有关系→可能看见"是二元的）。
**目标**：过滤权重从关系强度中计算。

**计算规则**：
- 规则过滤：有关系→看见概率 = 0.3 + 0.7 × relationship_strength
- 管家 LLM：关系强度作为 prompt 上下文注入（"你和XX关系很近，strength=0.8"）
- 无关系→看见概率维持当前默认（0.1）

### SOC-4: 关系影响记忆衰减

**当前**：记忆衰减率与关系无关。
**目标**：和亲密的人的对话记忆衰减更慢。

**计算规则**：
- emotional_slowdown = 1 / (1 + relationship_strength × emotional_weight × sensitivity)
- 亲密关系（strength > 0.7）的记忆衰减减速 2-3 倍
- 陌生关系（strength < 0.2）的记忆正常衰减

### SOC-5: 主动关系行为

**当前**：智能体不会主动改变关系。
**目标**：通过欲求系统触发关系行为。

**行为类型**：
- 主动关心：长时间未交互的亲密关系→欲求触发关心消息
- 关系修复：矛盾后 strength 下降→主动示好
- 关系探索：新用户→主动建立关系标签

**与欲求系统集成**：InnerNeedEngine 评估内心状态→关系欲求足够强→构造 prompt→调 LLM→发送关心消息。

## 约束

1. 关系强度变化必须可追溯（每次变化记录原因+时间）
2. 关系标签涌现不调 LLM（纯规则统计，保持 ≤5ms）
3. 感知权重变化是渐进的（不因单次交互剧烈变化）
4. 主动关系行为有冷却期（同一关系不频繁主动）
5. 不破坏现有管家三层过滤的核心逻辑（仅改变权重来源）

## 技术约束

### Python 特性（参见 `.shared/memo.md`）

- **match/case**：SOC-2 关系标签涌现的交互模式分类用 match/case
- **dataclass(frozen=True)**：关系强度快照（RelationshipSnapshot）用 frozen dataclass，更新用 copy.replace()
- **uuid7**：关系变化事件的 ID 用 uuid7（按时间排序，方便查询变化历史）
- **asyncio.TaskGroup**：SOC-5 主动关系行为的并发触发用 TaskGroup

### OpenClaw 借鉴（参见 `.shared/memo.md`）

- **Fallback 是产品决策**：SOC-1 关系强度演化失败不应静默 fallback 到旧值，应明确报错
- **Core stays plugin-agnostic**：关系动态化逻辑在 A_memorix 内部实现，核心只通过 Protocol 接口查询关系强度
- **Hot path 不重复发现**：SOC-3 管家过滤权重应在关系变化时预计算缓存，不在每次过滤时重新查询

## 验收标准

- [ ] SOC-1: 关系强度随交互演化，可查询任意关系当前 strength 和变化历史
- [ ] SOC-2: 关系标签从交互中涌现，低强度标签自动淘汰
- [ ] SOC-3: 管家过滤权重从关系强度计算，对比固定权重检索质量有提升
- [ ] SOC-4: 亲密关系的记忆衰减显著慢于陌生关系
- [ ] SOC-5: 智能体可主动发送关心消息，有冷却控制
- [ ] 全部 ruff 通过，MaiBot 启动正常
