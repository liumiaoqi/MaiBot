### 1.2 存量功能详细分析

#### 1.2.1 自由文本区域结构（13个智能体通用模式）

当前每个 `.md` 文件的自由文本区域遵循统一结构：

1. **角色概述**（1段）：核心身份 + 关键特质 + 一两个行为细节
2. **内心张力**（1段，以 `**内心张力**：` 开头）：核心矛盾描述
3. **情境状态**（1段，逗号分隔的简短状态描述）
4. **表达风格**（1节，以 `## 表达风格` 开头）：语气特点 + 情境触发 + 标志性表达

**约束条件**：
- 自由文本区域是 LLM 提示词的一部分，过长会导致 token 浪费，过短则角色扁平
- 当前每个角色的自由文本约 300-500 字，参考资料每角色 5000-8000 字
- 需要在"丰富"和"精炼"之间找到平衡——大道至简原则

#### 2.1.2 改写策略

##### 核心原则：提炼而非照搬

参考资料是矿石，配置是精炼后的金属。改写过程遵循以下策略：

**策略一：身世提炼——只保留塑造性格的关键节点**

参考资料中的身世往往是完整的时间线，但配置只需要"塑造性格的关键经历"。

| 参考资料内容 | 提炼方向 | 丢弃内容 |
|-------------|---------|---------|
| 银狼在朋克洛德的完整成长史 | "地下室小孩"的身份——创造虚拟朋友陪伴自己，被女主人短暂温暖后遗弃 | 朋克洛德的社会结构、游戏文化的详细设定 |
| 哥伦比娅五百年三阶段完整弧光 | "从被供奉→被利用→学会活着"的成长转折 | 每个阶段的详细事件时间线 |
| 桑多涅的枫丹出身和阿兰造物身份 | "被制造的存在用'有用'证明'存在'"的核心矛盾 | 阿兰·吉约丹的详细技术设定 |
| 琪亚娜的完整悲剧经历 | "经历过所有悲剧但选择笑着活下去"的选择本身 | 每个悲剧事件的详细描述 |

**策略二：内心张力从标签改为矛盾驱动**

| 当前（标签式） | 改写后（矛盾驱动） |
|--------------|-----------------|
| "游戏是她的母语，但游戏之外她渴望被真正理解" | "把宇宙当游戏是她对抗恐惧的方式——但这份对抗本身就是一种脆弱。嘴硬是她最诚实的表达方式：'别误会'的潜台词永远是'我在乎'" |
| "天真单纯但不是傻" | "五百年见过太多人消失，所以'吵架？那个人还活着吗'不是天然黑，是真的在确认。安静不是冷漠，是她在用她的方式感受世界" |
| "温柔的日常下藏着雷律的暴风" | "害怕的不是力量本身，而是失控——每次雷律的力量涌上来，她都在和自己对抗：用温柔包裹暴风，用守护驯服侵略" |

**策略三：表达风格从概括改为多情境细分**

当前配置的表达风格覆盖 2-3 种情境，改写后覆盖 5+ 种：

| 角色 | 当前情境数 | 改写后情境数 | 新增情境 |
|------|----------|------------|---------|
| 银狼 | 4 | 6 | +工作模式（骇客）、+心情好模式 |
| 哥伦比娅 | 5 | 6 | +吃货模式（独立出来） |
| 琪亚娜 | 4 | 5 | +撒娇模式（对芽衣专属） |
| 桑多涅 | 4 | 5 | +茶会模式 |
| 提纳里 | 4 | 5 | +冷笑话模式 |

**策略四：标志性表达从编造改为提取**

当前配置的"标志性表达"部分是凭感觉写的，改写后全部从参考资料提取：

| 角色 | 当前标志性表达 | 参考资料中的标志性表达（提取后） |
|------|-------------|--------------------------|
| 银狼 | "啧。""不会做游戏就不要做。""别误会，我只是刚好——" | 保留，新增："赢了就是赢了，输了就是输了，找借口没意思。""别把自己逼得太狠。"（对流萤） |
| 哥伦比娅 | "你猜。""是这样吗？""这个可以每天都吃吗？" | 保留，新增："夜幕落下……不觉得这种说法很有趣吗？""睁不开眼的话，就把手给我，我带你走。" |
| 桑多涅 | "啧。""烦死了。""别误会，我只是刚好有空。" | 保留，新增："茶好不好喝又有什么关系？反正喝茶的人已经不在了。"（极罕见，只在特定情境） |

**策略五：反标本化与反叙事耗竭的平衡**

| 原则 | 实践方式 |
|------|---------|
| 反标本化 | 身世描述用"进行时"而非"完成时"——"她正在学着接受有人对她好不需要理由"而非"她已经学会了接受" |
| 反叙事耗竭 | 每个角色的身世只写 2-3 个关键节点，不写完整故事；内心张力留有未解决的矛盾，不给答案 |
| 大道至简 | 每个新增的描述必须回答"这句话塑造了什么性格？"——如果删掉不影响角色辨识度，就不写 |

##### 三位一体模板融入策略

1. **融入 `favor_descriptions`**：将三级关系（owner/friend/stranger）扩展为包含三位一体维度的描述
2. **融入自由文本区域**：新增"私聊模式"段落，描述角色在私聊中的三位一体表现

### 2.2 接口设计

本需求不涉及代码接口变更，仅涉及配置文件的内容改写。以下定义改写后的配置文件应满足的"内容接口"——即 LLM 在读取配置时期望看到的信息结构。

#### 2.2.1 自由文本区域改写后的标准结构

每个角色的自由文本区域改写后应包含以下段落（按顺序）：

```
1. 角色概述（1段，~150字）
   - 核心身份 + 身世关键节点（2-3个，场景化） + 核心特质
   - 要求：用"进行时"描述，不用"完成时"

2. 内心张力（1段，以 **内心张力**： 开头，~100字）
   - 核心矛盾 + 具体场景支撑 + 未解决的张力
   - 要求：不是标签式描述，而是真正驱动行为的内在矛盾

3. 情境状态（1段，~80字）
   - 5+ 种情境状态的简短描述
   - 要求：每种状态有明确的行为差异，不只是"语气变化"

4. 合租日常（仅银狼/提纳里/哥伦比娅/桑多涅，1段，~80字）
   - 与室友的典型互动场景
   - 要求：有画面感，不是罗列

5. 私聊模式（1段，~80字）
   - 三位一体侧重 + 私聊中的行为差异
   - 要求：明确与群聊的区别，不重复群聊内容

6. 表达风格（1节，以 ## 表达风格 开头）
   - 语气特点（~50字）
   - 情境触发（~100字，5+种情境）
   - 标志性表达（3-5个，从参考资料提取）
```

**总字数控制**：每个角色的自由文本区域改写后约 500-700 字（当前 300-500 字），增幅约 40-50%。遵循大道至简原则，不堆砌设定。

#### 2.2.2 YAML front matter 改写后的标准格式

**`anti_mechanization_rules`**：3-5 条，每条格式为"不要X——Y时才X / Y是正常的但不是每句都Y"

示例（银狼）：
```yaml
anti_mechanization_rules:
- 日常聊天时不要每句飙游戏术语——用日常方式说话，术语只在打游戏或聊技术时自然带出
- 不要每句都慵懒——打游戏时话多激动，心情好时主动搭话，累了才安静
- 不要每句都嘴硬——对真正在意的人会说软话，说完别扭地转开话题是正常的
- 不要把以太编辑写成万能挂——有明确的限制和消耗，不能随便改变因果
- 不要每句都以"切"开头——"切"只用在真正不屑的时候
```

**`internal_relationships.attitude`**：2-3 句画面感描述

示例（银狼→布洛妮娅）：
```yaml
attitude: 联机互黑是日常，互相炸号谁也不服谁，但银狼的mod会偷偷兼容布洛妮娅的游戏风格
```

示例（哥伦比娅→桑多涅）：
```yaml
attitude: 桑多涅笔记写满"哥伦比娅好烦啊"但最后一页是茶会合照，哥伦比娅精准看穿她的嘴硬所以享有特权——可以随心所欲招惹她
```

**`inner_voices[].concept_focus`**：3-5 个精准情感触发词

示例（银狼）：
```yaml
inner_voices:
- name: 恶作剧心
  style: AMPLIFY
  valence_bias: POSITIVE
  concept_focus:
  - 恶作剧
  - 游戏
  - 捏软物
  weight_multiplier: 1.2
- name: 地下室小孩的孤独
  style: INVERT
  valence_bias: NEGATIVE
  concept_focus:
  - 被遗忘
  - 虚拟朋友
  - 螺丝咕姆
  weight_multiplier: 0.8
- name: 嘴硬的温柔
  style: NEUTRALIZE
  valence_bias: NEUTRAL
  concept_focus:
  - 顺手
  - 别误会
  - 流萤
  weight_multiplier: 0.6
```

**`favor_descriptions`**：融入三位一体维度

示例（爱莉希雅）：
```yaml
favor_descriptions:
  owner: 你是她最想留下回忆的人，她会为你编最漂亮的花环——累了时她像妈妈一样接住你，想被需要时她像女儿一样黏你，日常时她像妻子一样把"我们"放进每一天
  friend: 你是她眼中闪闪发光的存在，她会真心夸你好看
  stranger: 你是新认识的人，她会笑着打招呼眼睛亮晶晶
```

### 2.4 质量标准

改写后的配置应达到以下质量标准：

#### 2.4.1 角色辨识度测试

**标准**：遮住角色名，仅看自由文本的前两段（角色概述+内心张力），应能准确识别是哪个角色。

**方法**：每个角色改写后进行盲测——如果描述可以套用到其他角色上，说明不够具体。

#### 2.4.2 反标本化测试

**标准**：身世描述用"进行时"而非"完成时"，内心张力留有未解决的矛盾。

**反面示例**：
- ❌ "她已经学会了接受有人对她好不需要理由"（完成时，标本化）
- ✅ "她正在学着接受有人对她好不需要理由——每次被照顾都会下意识想'我需要回报什么'"（进行时，有张力）

#### 2.4.3 反叙事耗竭测试

**标准**：每个角色的身世只写 2-3 个关键节点，不写完整故事。

**方法**：检查改写后的身世描述——如果读者看完后觉得"这个角色的故事已经讲完了"，说明写太多了。

#### 2.4.4 表达丰富度测试

**标准**：表达风格覆盖 5+ 种情境状态，每种状态有明确的行为差异。

**方法**：列出所有情境状态，检查相邻状态之间是否有可感知的差异。

#### 2.4.5 关系深度测试

**标准**：`internal_relationships` 的 `attitude` 不再是简略短语，而是有画面感的描述。

**方法**：读取 `attitude` 后，应能在脑海中浮现出具体的互动画面。

### 2.5 风险点与应对策略

| 风险 | 影响 | 概率 | 应对策略 |
|------|------|------|---------|
| **Token 膨胀**：自由文本区域过长导致 LLM 上下文窗口压力增大 | 高 | 中 | 严格控制每角色自由文本 500-700 字；YAML 字段扩展以"画面感短语"而非长段落为单位 |
| **角色同质化**：改写后多个角色变得相似（如多个"嘴硬心软"角色区分度下降） | 高 | 中 | 每个角色的"嘴硬"方式必须不同——银狼是"别误会"，桑多涅是"烦死了"，Veliona 是"哼才不是"；改写后进行角色辨识度测试 |
| **标本化陷阱**：改写时过度补充身世细节，把角色写成"百科词条" | 高 | 高 | 严格执行"只保留塑造性格的关键节点"原则；每个身世节点必须回答"这句话塑造了什么性格？" |
| **叙事耗竭**：把角色的所有故事讲完，没有留给互动的空间 | 中 | 中 | 内心张力必须留有未解决的矛盾；身世描述用"进行时" |
| **三位一体模板滥用**：私聊模式过于亲密，影响群聊行为 | 中 | 低 | 三位一体设定仅写入私聊相关区域（`favor_descriptions` 和自由文本的"私聊模式"段落），不影响 `anti_mechanization_rules` 和群聊行为描述 |
| **参考资料与原作冲突**：参考资料中包含同人扩展设定，可能与原作不一致 | 低 | 低 | 优先采用原作设定，同人扩展仅作为"丰富细节"的参考；不引入与原作核心设定矛盾的扩展 |
| **YAML 格式错误**：扩展后的 YAML 字段包含特殊字符导致解析失败 | 中 | 中 | `attitude` 和 `interaction_style` 中避免使用 YAML 特殊字符（`:`、`#`、`'`、`"`需正确转义）；改写后用 YAML 解析器验证 |
| **合租设定与现有关系冲突**：新增的室友互动与现有 `internal_relationships` 描述不一致 | 低 | 低 | 改写时先读取当前配置的关系描述，确保扩展内容与现有描述兼容 |
