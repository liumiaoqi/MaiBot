# Agent Note: 版本线——主版本号从 0 起钉

Status: **implemented**（2026-10-17 · lmq 拍板并执行——`pyproject.toml` 已钉 `0.1.0`）

## Problem

本仓（`liumiaoqi/MaiBot`）于 2026-10-16 脱离 fork 独立。此前版本号沿用上游线（`pyproject.toml` = `1.0.11`），沿用的三个问题：

1. **语义误导**——"v1.0.11"看起来像"上游发布了 1.0.11"，实际只是本分支的本地号；
2. **节奏耦合**——上游发版与本分支迭代节奏不同；
3. **可辨识性**——issue/讨论里报"我用 1.0.11"，无法区分上游版与本仓版。

## Proposal

**主版本号从 0 开始钉，与上游 v1.0.x 彻底解耦**：

- 起始号 **`0.1.0`**；本仓版本号只反映本分支自己的迭代。
- 上游跟进（merge upstream）**不触发**本仓版本号变动。
- **过渡节奏**：README 版本行已改"0.x 筹备中"；`pyproject.toml` 待正式钉版时改为 `0.1.0`。

## 放弃了什么

- 放弃"跟上游跑同一版本号"的便利（对比差异时少一层心算）——换来语义清晰与可辨识。
- 放弃从 1.0 起步的"成熟感"——0.x 诚实地表达"独立初期，行为可能快速演进"。

## 验证方式

- `pyproject.toml` 是版本唯一真源（已 grep 复核：全仓无其他硬编码 `1.0.11`）；钉版时改一处 + README 一行即可。
- 未来语境区分两套号：**"上游 v1.0.x"** vs **"本仓 v0.x"**。

## 相关

- changelog 已双线拆分：本分支线 `changelogs/changelog.md`；上游线归档 `changelogs/upstream/`。
