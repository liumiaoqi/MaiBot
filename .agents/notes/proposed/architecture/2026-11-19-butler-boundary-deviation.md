# Agent Note: 管家边界 —— 从「不说话的空间逻辑」收敛为「唤起者丽塔」

Status: proposed（2026-11-19 用户表态后收敛为 A+ + C；B+ 作为可选补丁，待最终确认）

## Problem

角色定义（项目规则）：

> 管家不是第 14 个角色，是**彼岸居客厅的空间逻辑**人格化——「谁在客厅谁就回消息」。管家不说话，只做两件事：过滤（谁看见了消息）和协调（谁先抢到键盘）。

代码事实（2026-11-19 只读核验）：

- `src/maisaka/agent_autonomy/butler.py:642` `speak_and_send()` → `speak_self()` 调用 LLM（`request_type="butler_speak"`）生成回复；
- `butler.py:663` 通过 MessagePort 以 `agent_id=butler_id, source="butler_speak"` 发出；
- `orchestrator.py:1244` 主智能体沉默时管家接管，`context_hint="主智能体沉默了，需要你接管回复"`；
- `orchestrator.py:1285` 异常降级路径同样走管家接管；
- 频率证据：`agent_autonomy_speaker_change_records` 共 72 条，`butler_auto=12`（16.7%），`decision_source=rule` 12。

**更深一层**：代码里的管家不只是「兜底发言者」，而是**一个有名字、有人格的角色**：

- `butler.py:569` docstring：「管家以**丽塔的人格**自己发言。场景：主智能体 SILENT 时管家接管、引导话题、提醒等。」
- `butler.py:591-596` system prompt 注入 `_butler_personality`、`reply_style`、`internal_relationships`；
- `butler.py:612-614` user prompt：「你是{name}，客厅的守护者……可以是接话、引导话题、提醒、或者只是表达你的存在」；
- `speaker_transfer.py:49` `butler_takeover_threshold: int = 2` —— 接管 2 次即触发永久转移评估。

### 「没说完就结束」的机制

当前收尾链路（`orchestrator.py:1201-1254`）：

1. 主智能体 `SILENT` → `butler.update_primary_status("silent")`；
2. `decide_speaker_transfer(...)`：优先**永久转移**（换一个角色接话）；
3. 转移成功 → `_trigger_new_primary_think(...)` → 新角色说；
4. 无永久转移 → `butler.speak_and_send(...)` 管家代说；
5. 管家也失败 → 放弃（对话结束）。

即：**「结束」是 `SILENT` 的副作用，不是显式判定**。没有「话题是否展开、是否该再给一回合」的检查；丽塔代说的通常是一句引导/存在感，说完即收尾，所以观感是「话没说完」。

## 用户表态（2026-11-19）

- **喜欢让丽塔每次出来说话**；
- 丽塔的调度作用主要是**唤起 LLM**，不是强迫角色说话；
- 尴尬：加上丽塔共 14 个角色，经常「没有说完就结束」；
- 不调度成本又比较高（不唤起就不会有回复，体验损失大）。

## Decision（按用户表态收敛）

采用 **A+ + C**，B+ 作为可选补丁。**A+ 的定位在 2026-11-19 追加为「开场者 + 场景叙述者 + 唤起者」**：

- **开场**：用户的**第一句话**由丽塔先接——不是角色抢答，而是丽塔把场景立起来（时间、谁在客厅、当前氛围）；
- **场景描述**：整体场景由丽塔叙述；角色只在自己的「剧情层」里回应；
- **唤起**：场景立好后，丽塔优先转移给某个角色（唤起 LLM），其次才自己继续；
- **边界**：丽塔说「场景层」（谁在、何时、什么气氛），不代替角色说「剧情层」（角色自己的观点、情绪、关系表达）。

> 与 VSM 对应：丽塔承担 **S5（身份/场景）** 与 **S2（协调）**，角色是 **S1（操作单元）**。这也是「14 个角色」里她不算第 14 个表演者、但确实算第 14 个角色的原因。

- **C 话题预算**：每个话题给一个「唤起预算」（如最多 2 次代说/转移）；预算内尽量让角色把话说完，超预算才允许静默结束。
- **B+ 可选补丁**：仅当最后一条是**疑问 / 引导语**时，给一个额外回合让某个角色接；避免每次 `SILENT` 都多烧一次调用。

> 默认触发（待用户最终否决）：B+ 只在「疑问结尾」启用；A+ 的场景叙述只在「会话开场 / 新话题」触发，不是每轮都叙述。

## Alternatives considered

| 方案 | 做法 | 代价 | 收益 |
|---|---|---|---|
| **A. 改定义（原文）** | 承认丽塔是第 14 个角色，只限定「提示/兜底 N 次」 | 与「管家不说话」直接冲突；统计口径要改 | 改动最小 |
| **A+（采纳）** | 承认丽塔，但定义为**唤起者**：优先转移、其次代说；发言只做引导/提醒 | 需改写角色文档；需给「唤起」与「内容」分口径 | 与用户偏好一致，边界清楚 |
| **B. 改实现** | 删人格 prompt 与「表达存在」，沉默改系统提示或显式点名 | 改动大，需真机验证；可能失去用户喜欢的丽塔 | 回到「空间逻辑」 |
| **B+（补丁）** | 只在疑问/引导结尾追加一回合 | 多一次 LLM 调用 | 缓解「没说完」 |
| **C. 话题预算** | 每话题唤起次数上限，超限允许静默 | 需要判定「话题边界」 | 成本可控 |
| **D. 维持现状 + 记录** | 只加状态声明 | 文档与现实长期不一致 | 零改动 |

## Consequences

- **A+**：需在角色/管家文档里把「管家不说话」改写为「丽塔是开场者 + 场景叙述者 + 唤起者」；`butler_takeover` 要区分「场景发言 / 唤起 / 内容发言」；`butler_takeover_threshold=2` 要写进文档。还需定义「场景层」的数据来源（时间、在场者、氛围），并处理「丽塔先说」与「角色抢答」的优先级。
- **C**：需要定义「话题」边界（按 session + 时间窗，或按最后一次用户消息）；预算耗尽的降级必须可见（日志/统计），不能静默。
- **B+**：判定「最后一条是否疑问/引导」需要有可测试的规则（不能只靠 LLM 判断），否则成本不可控。
- **测试**：A+ 需断言「丽塔代说只发生在转移失败后」；B+ 需断言「仅在疑问结尾多一回合」；C 需断言「预算用尽后静默且记录」。
