# Agent Note: Phase 3 六项收尾决策（raw 下线 / 旧读两步走 / Git 留档 / F13 / 104 域 / 数据侧）

Status: proposed（2026-11-19 已拍板；#1 raw 下线与 #2(a) 死代码删除已于 2026-10-16 完成，剩余项待实施）

## Problem

Phase 3 新配置体系的**代码早已在主干**（六段 + 前端约束消费 + 前端接缝迁移，真机 `/config/get`、`/config/mutate` 已调通），但"替换"没有真正发生。原因是六项取舍一直悬着：

1. raw 端点要不要下线——它是密钥明文出站路径，也是 WebUI 手改 TOML 的唯一逃生舱。
2. 旧读路径要不要删——6 条里 4 条是纯死代码，其余 5 条两个前端都在用。
3. 留档策略——`.bak` 每次保存都写且永远带上一份明文，`old/` 无上限增长。
4. F13 锁优化——实测"下移线程池"单独做会让并发读把循环卡死。
5. 其余 104 个域接不接——19% 是非标量，`fieldHooks` 全是空壳，接了会写坏配置。
6. 数据侧批次——要动 3.5 个月真实运行史。

证据出处：`.shared/decisions/phase3_new_config_roadmap.md:163-175`；前端与接线实测见同文件 177-194。

## Decision

### 1. raw 端点：下线，按 dsh 的「引用 + 脱敏视图」模型

`GET /config/bot/raw` 删除，WebUI「源文件」页签同步移除。依据不是"少一个端点"，而是 dsh 的配置接缝本来就不提供原文：

- dsh `settings` 接缝只 serve **redacted layered descriptors**，原文留在 `settings-file` provider 内部（`docs/capability-seams.md:485`）；
- dsh `credentials` 接缝让配置只携带**引用**，API 暴露 value-free views + write-only storage（`:487`）；
- LLM 配置注释明确 prefer `apiKeyEnv`，使 **no secret enters configuration files**（`docs/config-catalog.md:3212`）。

对应到本仓：编辑原文的能力交给**本地文件**（配置本来就是本地文件），WebUI 只保留 schema / 条目视图；密钥走已有的 `role('secret')` 引用路径。

**状态：已完成（2026-10-16）。** 实测当前 `mingtang/openapi/openapi.json` 中 `bot/raw` 零命中；`src/webui/routers/config.py:2016` 注释记录下线与前端页签同批移除。删除提交 `1e74e934b` 位于 `agent-presets` / `cache-prefix` / `cfg-dash-raw` 分支，main 的代码状态等价。

### 2. 旧读路径：a → b 两步，全迁前端后再删

- **a（已完成，2026-10-16）**：删除 `adapter-config` 四条死代码端点——两个前端各 0 处调用，唯一引用是一条测试。当前 `src/webui/routers/config.py` 与 OpenAPI 快照均零命中；守护测试 `TestAdapterConfigEndpointsAreRetired` 已存在（`pytests/webui/test_config_seam.py:1631`）。
- **b（独立批次）**：把其余 5 条旧读的前端消费迁到新接缝。这一步包含两件**今天不存在**的逻辑：
  - 旧读返回嵌套对象 → 新读返回扁平条目表，需要「扁平↔嵌套」适配；
  - 写路径需要 **409 revision 冲突分支**。
- **b 验收通过后**才删其余 5 条旧读端点。不做"边迁边删"。

### 3. 留档策略：本地 Git 小仓自动管理

在**每个有配置的目录**（如 `docker-config/mmc/`、`data/MaiBot/` 的配置层）初始化独立的本地 Git 仓，保存动作后自动 `git add` + `git commit`，用 Git 历史接管 `.bak` 与 `old/`。

约束：

- **不推远端、不进主仓**——密钥明文只留在本地历史，与 `.bak` 同级风险，不扩大到共享历史；
- 首次提交作为基线；此后每次保存一次提交（message 带操作类型与时间）；
- `.bak` 与 `old/` 停止新增，迁移完成后可删；
- 回滚用 `git revert` / `git checkout <sha> -- <file>`；
- 容器不得读取这些 `.git` 目录（需 `.dockerignore` / 挂载检查）。

实现口径（2026-11-19 定）：

- **在容器内执行 Git**：配置保存点在 `maim-bot-core` 进程内（`docker-compose.yml:49` 把 `./docker-config/mmc` 挂到 `/MaiMBot/config`），容器自带 git 2.53.0；`.git` 随挂载落回宿主持久化，容器重建不丢。
- **commit 必须在保存锁外异步执行**：保存路径持锁中位 248ms，Git 操作不得进入锁内，否则把 F13 的优化直接退回。
- **单 worker 串行**：Git `index.lock` 不允许并发写；两次快速保存必须排队，不能并发 commit。
- **失败双通道**：logger + `last-git-commit.json`（失败原因 / 时间 / 目标文件）；写盘成功但 commit 失败必须可见，不静默降级。

### 4. F13：先收窄锁范围，再评估下移

取 (a)。锁内只保留「读字节 + sha256」（实测 0.28ms），把 pydantic 解析挪到锁外，先把 248ms 压到约 56ms；之后单独实测再决定是否下移线程池。**不取 (b)**——实测下移后并发读会把循环卡死（340ms，比现状 271ms 更差）。

### 5. 其余 104 域：先接 3 个纯标量高约束域

取 (a)：先接 `agent_autonomy`（46 字段 / 29 约束）、`chat`（22/10）、`a_memorix.integration`（22/14）。零新控件、立刻有可见收益。

同时把 (b) 的 8 类复杂字段编辑器定为**下一批硬前置**——19% 非标量不解决，其余域不能接，否则会写回类型不符的值。

### 6. 数据侧：暂不立项，先做只读基线

取 (b)，但先完成三件只读准备：备份 `data/MaiBot`、导出表清单与行数/时间范围、列出可重建与不可重建的表。基线摸清后再立项；不在没有基线时动真实运行史。

## Alternatives considered

- **raw 只给非密钥原文（原选项 c）**：与 dsh 模型不一致，且"脱敏原文保存回去"会把占位符写成真密钥，比不做更危险——拒绝。
- **raw 加二次确认（原选项 b）**：只降低误触，不消除明文出站——拒绝。
- **旧读路径一次全删**：5 条仍被前端使用，会直接打断配置页——拒绝。
- **只做 a 不做 b**：桥接层永久存在，旧读路径成为第二条真源——拒绝。
- **留档用 `.bak` 保留最近 N 份**：仍是明文副本，且与"绝不覆盖已有留档"的现行注释冲突，要同时改制度与测试——不如 Git 直接接管历史。
- **F13 只下移线程池**：已被实测否掉（并发读卡死）。
- **104 域全接**：19% 非标量字段的 `fieldHooks` 是空壳，会写坏配置——拒绝。
- **数据侧立即立项**：没有基线就动 3.5 个月运行史，风险不可控——拒绝。

## Consequences

**实施顺序（批次不得并行）：**

1. #2(a) 删 4 条死代码（已完成，2026-10-16）
2. #1 raw 下线 + 前端页签移除（已完成，2026-10-16；端点形状已变）
3. #3 Git 小仓接管留档
4. #2(b) 前端接缝迁移（含扁平↔嵌套适配与 409 分支）
5. 删其余 5 条旧读路径
6. #5 接 3 个纯标量域 + 8 类编辑器
7. #4 F13 收窄锁
8. #6 数据侧基线 → 立项

**与契约层的关系**：#1 会删除端点、#2 会改读/写接缝，都会改变 `openapi.json` 的形状。因此**先完成 1–5 再补 `response_model`**，否则补完模型又要随端点删除重写。

**验证方式**：

- #1：`rg` 确认前端无 `raw` 调用；契约快照重新生成，路径数下降且无残留引用；密钥字段不出现在任何 API 响应。
- #2：a 步后全量测试零新增失败；b 步后旧读路径 grep 期望 0，且 409 分支有测试。
- #3：保存一次后 `git log` 有对应提交；容器内读不到 `.git`；回滚演练成功。
- #4：`commit` 持锁中位从 248ms 降到约 56ms；并发读不再卡死。
- #5：三个域保存后类型往返一致；非标量域**未接**（显式登记）。
- #6：基线三件产出（备份 / 表清单 / 可重建判定）。

**风险**：

- Git 小仓含密钥明文，必须坚持"不推远端、不进主仓"，并确认容器不挂载 `.git`。
- raw 下线后失去"写坏自救"通道；需在文档中明确"改原文走本地文件"的操作路径。
- 删端点会破坏基于旧快照的契约产物，必须同批重新生成并审 diff。- **回滚约束（G2）**：#1 与 #2(a) 在同一提交 `1e74e934b`，且该提交不在 main 的祖先链上（位于 `agent-presets` / `cache-prefix` / `cfg-dash-raw` 分支）。无法单独回滚——要恢复 raw 只能整体恢复该提交，代价是同时恢复 4 条死代码端点与前端页签。故本决定选择**不回滚**。
