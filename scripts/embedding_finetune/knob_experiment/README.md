# 旋钮实验（Knob Experiment）— 参数指向性观测

> 实验动机（lmq，2026-08-05）：每个参数就是一个"旋钮"。
> 用指向性极强的数据训练极小模型，观察参数是否产生"指向性"；
> 多种不同指向的数据训练后对比参数轨迹；根据观察手动修改参数走向。

## 实验问题

1. 极小模型（~150 参数）训练后，参数是否会出现"指向特定数据模式"的局部对应？
2. 同一初始参数用 A/B 两种指向数据训练，参数终值的差异（轨迹）能否可视化？
3. 手动把"指向 A"的参数拉向中间，A/B 准确率的 trade-off 如何变化？

## 环境

- 复用 `scripts/embedding_finetune/` 训练环境（uv 管理，torch + matplotlib）
- 运行（Windows 侧 uv）：`uv run python knob_experiment/<script>.py`
- 独立目录，不干扰微调脚本

## 核心结论（已实证）

1. **参数有"指向性"（统计层成立）**：610 参数训练后，90 个明显偏向横条纹、13 个偏向竖条纹——参数确实朝数据方向走
2. **单个旋钮拧不动结果（操作层不成立）**：把"指向 A"的 Top5 参数拉回中间，A/B 准确率纹丝不动——**指向性是分布式的，要拧一组协同的旋钮才有效**
3. **架构决定指向性形态**（跨架构对比）：
   - 更深/更宽模型 = 更分布式（集中度 mlp2 9.8% → mlp3 3.6% → wide 2.1%）
   - CNN 完全不分化（0/0/354）——卷积核共享结构把指向性抹平
   - 没有任何架构让"单旋钮"变得可操作

## XOR 实验结论

- 单层感知机学不会 XOR（输出恒 0.5 猜硬币）——线性不可分
- 加隐藏层就学会（0.01/0.98/0.98/0.02）——**隐藏层把输入"变形"到可分的位置**
- 这是"智能来自哪里"的最小证明：逻辑不在输入里，是隐藏层创造出来的
- 输出 `xor_inference.png`：4 种输入的隐藏层激活模式对比

## CPU/GPU 架构对比（cpu_arch.py 实证 + 理论）

### 硬件本质

- **GPU** = 几百条并行流水线（SIMT 单指令多线程）：吞吐极高，只能干"同规格大批量"的活
- **CPU** = 几个全能老师傅：处理复杂逻辑/分支/顺序判断，灵活但吞吐低

### 架构匹配原理

| 运算模式 | 匹配谁 | 为什么 |
|---|---|---|
| 矩阵乘（GEMM） | GPU | 输出元素互不依赖——几千核各算一个 |
| 注意力 O(n²) | GPU | 就是大规模矩阵乘 |
| 递推/扫描 O(n) | CPU | 每步依赖上一步——顺序执行是 CPU 的模型 |

**Transformer 是"为 GPU 而生"**（注意力 = 并行矩阵乘）；**SSM/Mamba 是"为 CPU 而生"**（递推 = 顺序执行）。

### 实测（交替序列预测，CPU 扫描 2000 步）

```
              参数量   自回归准确率   CPU 扫描 2000 步
MLP(矩阵并行)   49     100.0%        33.1 ms
SSM(线性递推)    5     100.0%        23.9 ms   ← 快 28%
```

SSM 学到的 5 个旋钮（a≈0, b≈-1, c≈1, d≈1）就是数学解：`输出 = 1 - 输入`——递推把规律浓缩在状态 h 里。
实验发现：无输出偏置 d 时 SSM 学不会（线性递推表达不了"0→1"的常数项）——**真实架构的 bias 不是可有可无的**。

### 优劣对比

| 维度 | GPU 架构（Transformer） | CPU 架构（SSM/线性递推） |
|---|---|---|
| 训练 | 高度并行，GPU 上极快 | BPTT 长链难并行——训练慢 |
| 推理成本 | O(n²) 注意力，长序列指数贵 | O(n) 递推——每步 O(1) |
| 长上下文 | 全局注意力强 | 状态压缩有遗忘（有限状态） |
| 部署 | 离不开 GPU 集群 | CPU/手机/边缘设备可跑 |
| 内存 | KV cache 随序列暴涨 | 状态固定（几 KB） |
| 单点延迟 | 高（批次等待） | 低（流式逐 token） |

### 天生适合的任务

- **GPU 架构（Transformer）**：离线大规模理解（搜索/摘要/翻译/embedding 检索）、训练阶段、需要全局关联的任务（长篇文档/代码分析）
- **CPU 架构（SSM/线性）**：流式实时生成（对话逐 token）、长序列生成（O(n) vs O(n²) 差距随长度拉大）、边缘/嵌入式部署、低延迟单点推理
- **现实是混合**：训练用 GPU 集群（并行优势），推理时蒸馏/量化/稀疏化到 CPU 可跑的小模型——"训练重、推理轻"是趋势

### 前沿方向

1. Mamba/RWKV/Titans：注意力 → 线性递推（O(n) 推理）
2. 稀疏 MoE：每 token 只激活部分专家（计算量减半）
3. 量化：INT4/INT8（llama.cpp 让大模型跑 CPU）
4. 端侧 NPU：手机 AI 芯片

**一句话**：GPU 架构赢在"训练和全局理解"，CPU 架构赢在"推理成本和实时生成"——批量生产用流水线，单件定制找老师傅。
