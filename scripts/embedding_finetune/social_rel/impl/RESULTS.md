## 0. 一句话结论（三条，每条都能被下面某条命令推翻）

1. ⭐ **`+1` 发动机迁移成立，而且打满上限**：把「加强**该动的那位**」用在关系强度上，学出来的权重与真值
   的 Spearman **恰好等于该信号自己的信息天花板**（比值 **1.000**）—— ρ `+0.6036` vs 上限 `+0.6036`。
2. ⭐⭐ **分界线是「信号里有没有方向信息」，不是「用不用标签」**（lead 2026-09-27 改判，本线独立复现）：
   5 条臂里，**用了标签但只有标量对错**的 `selected` 与**不用标签**的 `hebbian`/`freq_self` 一样学不动；
   而把频次本身改成"带方向"（`freq_link=anti`），**同一个`hebbian` 立刻显著**（ρ `−0.4689`, p `0.0005`，方向是反的）。
3. ⚠️ **「per-边稳态是守门人」这一半不迁移 —— 它压得住整体推高，代价是排序质量**：
   `hebbian` 的整体推高 `+0.1089 → +0.0045`（压 24×，✓ 这一半成立）；
   但 `contrast` 的 ρ `+0.6036 → +0.3376`、`boostonly` `+0.4454 → +0.3298`（✗ 这一半不成立）。
   机制原因见 §8：**WB 的稳态封的是"跨输出的空间总量"，本世界的稳态封的是"单条边的时间累积"**，
   而时间累积正是学会的机制本身。

## 2. 设计（一眼能看清"对照差在哪一个变量"）

**世界**（`gen_synth.py`，seed=0）：60 个人 · 600 条边 · 每条边注入真值强度 `w* ~ U(0.05, 0.95)` ·
互动总数 `T = 2706` 次 · 度分布 min/中位/max = 12/20/34 · 人人的关联边都 ≥ 5（60/60 可评估）。

初始权重 `w0 = 0.3` —— **对齐现状**：`cognitive_store.py` 的 `confidence REAL NOT NULL DEFAULT 0.3`。

**两路事件流（同一条日程，唯一差别 = 是否暴露 valence 标签）**

| 路 | 学习者能看见 | 与 `w*` 的关系 |
|---|---|---|
| `freq`（纯频次） | 每条边被互动了**几次** | **构造上无关**（|ρ| ≤ 0.02，拒绝抽样做实在样本上） |
| `pref`（显式偏好） | 每次互动的 **valence ±1** | `P(+1) = 0.15 + 0.70·w*` ⇒ 唯一携带 `w*` 的通道 |

> ⭐ **为什么要"同一条日程"**：这样"两路"的差别就只剩**标签可见性**这一个变量，
> `hebbian` 在两路上**必须逐元素相同** —— 程序里做了断言，实测 `True`（见 §3），这是对照设计自检点。

**7 条更新臂**（每条 = 一种"信号来源"）

| 臂 | 动谁 | 用标签? | **有方向信息?** |
|---|---|---|---|
| `hebbian` | 强化**外部记录到的那条** | ❌ | ❌ |
| `freq_self` | 强化**自己选中的那条**（自选择） | ❌ | ❌ |
| `boostonly` | 只加强**标签说该动的那条** | ✅ | ✅ |
| `contrast` | 加强该动的、削弱不该动的 | ✅ | ✅ |
| `selected` | 削弱**自己的头号选择**（只有标量对错） | ✅（仅标量） | ❌ |

**守门人（三臂归因）**：`off`（纯累积）· `cap`（只硬封顶）· `leak`（泄漏回基线 + 硬封顶，申报值 `LEAK_DEFAULT = 24`）。
硬封顶 `cap = 1.0` 是**现实现实约束**：`unified_profile_service.py:115` 就是 `min(1.0, max(0.0, edge.weight))`。

**增量 `lr` 是数据导出的唯一值**：`lr = (cap − w0) / max(n_e) = 0.7/29 = 0.02414`（见 §9，这一条是踩坑踩出来的）。

## 7. ⭐ lead 的两条评估硬约束（都在表里，不是口头承诺）

### 约束一：coverage 与 selection **必须两个数同时给**

主网格里 `cov1` / `sel1` / `sel1|cov` **三列并排**。**同一批 run 里报哪个，结论就反过来**：

| 同一批数字 | cov1（真值 top-1 有没有进我的 top-5） | sel1（真值 top-1 是不是我的第 1 名） |
|---|---|---|
| `contrast/leak` | **0.3500** > 机会 0.263 ⇒ 「有改善」 | **0.0500** < 机会 0.050 ⇒ 「没改善」 |
| `contrast/off` | 0.5250 ≫ 机会 | 0.1658 > 机会 |

⚠️ **并且要把分辨力一起说**：n=60 人时 `sel1` 的标准误 ≈ `0.023~0.030`（95% 分辨带 **±0.058**），
所以 `sel1` 那一列**只能分辨 0.06 以上的差**；`cov1` 的标准误 ≈ 0.057（分辨带 ±0.112）。
⇒ 主判据用 **ρ / nDCG / hit@5**（连续量、200 次集成），`cov1`/`sel1` 作为**必报的伴随列**而不是唯一判据。

### 约束二：候选摆放必须随机化（否则会得到恒绿判据）

**实测控制**（`E2` 判据，程序机械判定）：恒定分数探针（`fixed` 基线）的
`hit@5 = 0.2608` vs 机会水平（`random`）= `0.2591` ⇒ **落在机会水平，没有"永远选左边"式的恒绿**。

实现上：并列分数**每列都用随机拆并列种子**（`TIE_SEEDS = 0..19`，多列取平均），
所以"全部权重相同 ⇒ 靠位置取胜"这条路被堵死。

## 8. ⭐⭐ 归因：守门人到底管什么（H1 的第二半 —— 不迁移）

`leak` 强度跨 **200×** 扫描（6 → 1200），**结论对强度不敏感**：

| | ρ: `off` | ρ: leak 全区间 | 整体推高（封顶前均值位移）off → leak |
|---|---|---|---|
| `contrast` | **+0.6036** | +0.4386 / +0.3376 / +0.3256 / +0.3262 / +0.3376 / +0.3397 / +0.3369 | +0.0006 → +0.0000 |
| `boostonly` | **+0.4454** | +0.3565 / +0.3298 / +0.3260 / +0.3173 / +0.3147 / +0.3173 / +0.2973 | +0.0548 → +0.0023 |
| `hebbian` | +0.0171 | +0.0175 … −0.0325（全在零带内） | **+0.1089 → +0.0045（压 24×）** |

⇒ ⭐ **两半各说各话**：
- **(i) 压整体推高：成立** —— `hebbian` 的 `+0.1089 → +0.0045`，且它**不改变"学不学得会"**（两臂 ρ 都在零带内）。
  **这正好是 WB 的原结论**（"稳态只压整体推高，对正确率无影响"）。
- **(ii) 不影响学会与否：不成立** —— 在**有方向信息**的两条臂上，`leak` **一律劣化 ρ 0.08~0.27**，7 个强度、200× 区间无一例外。

**机制原因（可证伪）**：WB 的 `homeo` 是 **per-MBON** 的——它封的是**一个单元跨全部输出**的总量（空间维度）；
本世界的稳态封的是**一条边跨全部事件**的累积（**时间维度**）——而时间累积正是"从多次弱证据里平均出信号"
这件事本身。二者**同名不同物**。
**证伪它的那条命令**：跑 `learn.py --no-extra`，读「区分度体检」里 `pref/contrast/leak` 的 `封顶率 = 0.000`
—— 即**稳态臂根本没有碰到封顶**；于是"稳态 = 封顶式的守门"这个解释站不住，唯一剩下的作用就是**时间加权**。
（反过来说：若谁能让 `leak` 在**不降 ρ** 的前提下压住整体推高，本条即被推翻。）

## 9. ⭐ 一处**设计缺陷**的完整记录：`+1` 是**无量纲**的

> 这一节不是结论，是**走过的路**——因为它是本线唯一一次"差点把事故当发现"的地方。

**症状**：第一版照搬字面 `+1`（`lr=1.0`），`leak` 臂的 ρ 恒为 `+0.3227`，且**与 leak 强度完全无关**：
`leak=6/12/24/48` 之间 `ρ(w) = 1.000000`（排序逐元素相同）。当时的候选解释是"稳态就是没用"。

**归因**：本世界量程 = `[0.3, 1.0]`（宽 **0.7**），而一条边的累积量可达 **±16**。
⇒ 字面 `+1` 下**第一条事件就把权重打到顶**，此后 leak 再强也来不及把它拉回来；权重被钉死在
"首/末一次事件"的价上，**跨事件累积从未发生**。所以那个 ρ ≈ 0.32 是**"单次事件价 vs w*"的相关**，不是学习结果。
**失效的不是机制，是量纲。**

**修法（数据导出，零自由度）**：`lr = (cap − w0)/max(n_e) = 0.7/29 = 0.02414`
—— 让"某条边每一次都是 +1"这种最极端的情况**刚好**落进量程。给定世界，lr 唯一确定。

**对照表（同一批代码、只差 lr；`learn.py --literal-plus-one` 复现）**

| 档 | `contrast/off` ρ | `contrast/leak` ρ | `hebbian/off` ρ | `hebbian/off` hit@5 | 并列 |
|---|---|---|---|---|---|
| 字面 `+1`（lr=1.0） | +0.5593 | +0.3227 | **n/a（全常数，599/600 并列）** | 0.2558（= 机会水平） | 599 |
| 标定 lr=0.02414 | +0.6036 | +0.3376 | +0.0171 | 0.2725 | 581 |

⭐ **附带工程结论（直接可用在 H3 接入）**：`confidence` 的量程是 **[0,1]**
（`unified_profile_service.py:115`），所以**更新增量必须按量程缩放**——原样 `+1` 会把第一条事件就顶到天花板。
**证伪它的那条命令**：`learn.py --literal-plus-one`，看 `hebbian/off(lr=1)` 那行的 ρ = `n/a`、并列 = `599`
（即权重退化成常数）。

## 13. 局限（本线**没有**证明的东西）

1. **合成 ≠ 真实**：`w*` 是注入的，`P(+1) = 0.15+0.70·w*` 是**构造**的耦合。真实关系强度的真值**不存在**，
   `NOTES.md` §3.1 的②③两层（接入层 Recall@k/MRR/nDCG、选择层 coverage）**本线一格都没测**。
2. **`freq` 路学不动是设计性质，不是发现**：它的次数被**构造为**与 `w*` 无关（`|ρ| ≤ 0.02`）。
   本线能提供的是 `anti` 对照臂（§10）与"同日程"的严格隔离，**不是**"真实互动频次学不动"的证据。
   > ⚠️ 与 lead 通报的证伪者结果（`freq_passive` 成对排序率 **0.9924**，学得动）**不矛盾**：
   > 他们那边的"外部日记频次"**带了方向**；本线的 `freq` 路**故意不含方向**。
   > 两者合起来正好是"分界线是方向信息"的**两侧**。
3. **`sel1` 在 n=60 人下分辨力不足**（95% 带 ±0.058）——第③层"选择"这一环本线**只能说量级、不能说差异**。
4. **没有极性 / 没有结构泛化 / 单机单进程**：只测了"同一批边上权重 vs 真值"，没测跨人泛化、没测新边冷启动。
5. **`leak` 的不迁移是"在本世界"的结论**：本世界的量程被 `[0,1]` 钉死。若权重量程允许累积
   （如 WB 那条线），守门人的代价可能消失——**这是可继续追的方向，本线没测**。
