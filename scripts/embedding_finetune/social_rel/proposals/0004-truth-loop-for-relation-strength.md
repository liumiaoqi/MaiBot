## 二、设计（最小可用 · 只做一件事）

> **一句话**：让**用户的一个显式动作**能改写**某条关系的强度**，并把该动作**留痕**。

### 2.1 三条硬约束（都是从今天的实测反推出来的）

| 约束 | 为什么 |
|---|---|
| ⭐ **真值先于痕迹**（§4.5 顺序定律）| 实测定量：无真值时把覆盖率从 12% 拉到 75%，效果**变差 3.7×**（−0.0139 → −0.0520，p=8.4e-6）；有真值时同样的动作**翻倍**（+0.0467 → +0.0924）⇒ **`record_access` 那类"痕迹"必须在真值存在之后** ✓ |
| ⭐ **不做自动推断** | 结构侧已被测成"控制度后归零"（§1.24）⇒ 任何"从图/文本猜强度"的做法都是**伪造真值** ✓ |
| ⭐ **不复活 DEL-1** | `memory_feedback_*` / `fuzzy_modify_*` 两族（21 个字段）是 DEL-1 有意删掉的（§1.34）⇒ **本申请不碰它们**，另起最小路径 ✓ |

### 2.2 最小改动面（三处，都是"加"，不改现有语义）

| # | 改哪 | 怎么改 |
|---|---|---|
| **1** | **一个显式动作的入口** | 在**已有的**记忆查询工具结果里，允许调用方对**某条关系**打一个**两档/三档**的显式标记（例如 `raise` / `lower` / `neutral`）。⚠️ **具体入口形态由 lmq 定**（聊天指令 / 工具参数 / UI 都行）——**这是唯一需要他决定的接口问题** ✓ |
| **2** | **一张留痕表**（新表，不复活旧表） | `relation_feedback_events(relation_hash, action, actor, created_at, source_note)`——只增不改，作为**真值账本** ✓ |
| **3** | **把动作接到已有的写入点** | 复用**已存在且已测试**的 `v5_memory.py:104`（S1 那次改的函数）：`raise` → `confidence += δ` · `lower` → `−δ`（**已有上下界 `[0,1]`** ✓）· 并把事件写进 #2 的表 ✓ |

### 2.3 明确**不做**

- ⛔ 不碰 `memory_feedback_*` / `fuzzy_modify_*` / `paragraph_vector_backfill` 等 DEL-1 遗产；
- ⛔ 不做"自动判重要"（结构/文本推断已被证伪）；
- ⛔ 不改检索主链（`dual_path` / `graph_relation_recall`）；
- ⛔ 不在本申请里动 `episode` 那 552 条屏蔽（**那是零节的事，与这里独立**）✓
