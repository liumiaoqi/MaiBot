## 1. 反例① —— 随机权重是不是也一样好？

**判决：反例不成立**（指标分得开「学到」与「没学到」）。

**证伪条件（动手前写死）**：`|mean(成对排序率｜监督上界) − mean(成对排序率｜随机权重)| ≤ 3·se(随机权重)`。

**跑出来的**（20 seeds，阈值 3·se = 0.0663）：

```
监督上界 成对排序率 = 0.9958 ± 0.0081
随机权重 成对排序率 = 0.5227 ± 0.0964  (se = 0.0221)
差值 = 0.4731   阈值 3·se = 0.0663   （7.1 × 阈值）
不学(do-nothing) 部署选择准确率 = 0.5001 （= 永远是左的结构偏向，随机摆放后 = 0.5）
```

**⭐ 顺带抓到的一条（我协议里的必要条件）——位置偏置**：

```
随机左右摆放   : 永远选左 = 0.5001   ← 本协议（位置与真值无关）
固定'强者在左' : 永远选左 = 1.0000   ← 若评估不随机摆放：什么都不学也满分
```

⇒ 这条不是细节：**评估集若不随机摆放候选顺序，"不学"就是满分**。
本线后续任何人报"某某机制达到 100%"，必须先回答"你的候选顺序是怎么摆的"。

## 2. 反例② —— 纯频次信号是不是真的学不动？（H2 的直接检验）

**判决：⛔ 反例成立 —— H2 的两半都被证伪。**

### 2.1 先把 H2 拆开（不然它测不了）

H2 原话把**三个不同的信号**并成了两个词：**「纯频次 / "互动好坏"」**。

| 我实现的组 | 它到底知道什么 | 用标签？ | 成对排序率 | Δ vs 不学基线 | 判决 |
|---|---|---|---|---|---|
| `freq_passive` | **外部日记的频次**（谁常出现） | 否 | **0.9924** | +0.4924 | ★**学得动** |
| `freq_active` | **自己选择的计数**（无结果反馈） | 否 | 0.4773 | −0.0227 | 学不动（且**低于**基线） |
| `reward_1sided` | 标量对/错（WB `selected` 迁移版） | 否 | **1.0000** | +0.5000 | ★**学得动** |
| `reward_1sided_clamp` | 同上 + 权重有下界 [0,1]（初值 0.5） | 否 | **1.0000** | +0.5000 | ★**学得动** |
| `reward_sym` | 标量对/错（REINFORCE 形态 ±1） | 否 | **0.9928** | +0.4928 | ★**学得动** |
| `label_boost_err` | 「该选的那位」 | **是** | 1.0000 | +0.5000 | 学得动 |
| `label_boost_err_cap` | 同上 + per-实体封顶 | **是** | 0.8409 | +0.3409 | 学得动，**但被封顶拖累** |
| `label_contrast` | 真赢家 +1 / 真输家 −1 | **是** | 1.0000 | +0.5000 | 学得动 |
| `label_boost_all` | 监督上界 | **是** | 0.9958 | +0.4958 | 学得动（正对照） |

（基线 `none` = 0.5000 · 噪声尺度 `random_w` = 0.5227，se = 0.0221，阈值 3·se = 0.0663。完整表见附录。）

### 2.2 两半的判决

- ⛔ **「频次」半边被证伪**：`freq_passive` 在**没有任何反馈信号**的情况下 0.9924（基线 0.5000）。
  ⇒ 「纯频次」不是一个信号，是**两种答案相反**的东西：
  - **外部日记频次**（谁常出现）—— **含真值信息** ⇒ 学得动；
  - **自己选择的计数** —— 无结果反馈、无真值信息 ⇒ 学不动（0.4773）。
  ⇒ 这两半答案相反 ⇒ **H2 的原措辞必须拆开重写，否则它不是一个可证伪的表述**（无论结果如何都能自圆）。
  ⚠️ **诚实标注这一半的边界**：`freq_passive` 的日记按 `p ∝ 真值强度` 抽样 ⇒ 它**预设了
  "互动频次与关系强度同向"这一世界模型**。信号本身仍只是**计数**（含噪、拿不到真值），所以不是作弊；
  但它的可学性**完全取决于数据生成过程** —— 而这正是 H2 没写出来的那一半：
  **"纯频次学不学得动"不是学习器的性质，是世界模型的性质**。
  ⚠️ **对本线的直接含义**：若 MaiBot 里现成的"激活频次 / 互动次数"确实与关系强度同向，
  那它**不是一个 do-nothing 基线**（本实验里它是 0.9924），
  ⇒ 「比现有实现好」这句话里的**"现有实现"必须按 0.9924 那一档来比，不能按 0.5000 比**。
- ⛔ **「互动好坏」半边被证伪**：`reward_1sided` / `reward_1sided_clamp` / `reward_sym` **不用任何标签**却学得动
  （1.0000 / 1.0000 / 0.9928，选择准确率同量级）。
  ⇒ 「必须显式偏好信号」在我这个形态下**不成立**。

### 2.3 归因（D 段）—— 这不是"任务太容易"

一个 1.0000 的结果必须回答"是不是我构造得太简单"。**扫 k 选一**（k=2/3/5/12）：

```
  k                   组        成对排序率     Δ vs 不学       选择准确率      随机猜        判决
  2       reward_1sided       0.9985     +0.4985      0.9988    0.500      ★学得动
  3       reward_1sided       0.9909     +0.4909      0.9997    0.333      ★学得动
  5       reward_1sided       0.9295     +0.4295      0.9986    0.200      ★学得动
 12       reward_1sided       0.5833     +0.0833      1.0000    0.083      ★学得动
```

⇒ 到 k=12（每题都把全部 12 个候选摆出来）还是学得动 ⇒ **不是难度问题**。

**机制解释（为什么会这样）**：纯奖励下有**两段**信息 ——
①「我选了谁」（自己知道）+ ②「对还是错」（反馈给）⇒ 合成起来就是**方向**：
**错 ⇒ 被我选中的那个是错的 ⇒ 降它**。而"谁更弱"是会被**更频繁地选中并出错**的，
所以降的量是真值的单调函数。

**旁证（为什么这不是"记忆对级结果"）**：参数化是 **per-实体一维**（12 个参数），
它**没有能力**记住 66 个对级结果；却能把全部 66 对排序正确 ⇒ 学到的是**实体级强度序**。

**⚠️ 我这条结论的翻案条件（写清楚，方便别人来打）**：
若读出带**固定正基线 + 单位封顶**，使"降"无法穿越基线（= WB 那种形态），
那么"只知对错"确实可能锁死 —— **这正是我与 WB 的形态差异**，不是我的实验精度不够。

> 我**试图复现** WB 的 50% 锁定而**失败**：`reward_1sided_clamp`（权重限 [0,1]、初值 0.5，
> 即"有界 + 有底"）也是 **1.0000**。
> ⇒ **50% 是 WB 那个读出形态的性质，不是"纯奖励"的普遍性质**；把它的结论原样搬到
> "共享一维、无固定正基线"的关系权重学习上，**在我的协议下不成立**。

- ⇒ 同一个 run：**①层满分、②③层仍是旧基线**。只看 coverage 的报法**看不到这一列**。

### 3.3 指标分辨力锚点（否则"变好"是空的）

```
oracle（喂真值=正对照）      Spearman 1.0000 · 成对排序率 1.0000 · top1 1.0000 · 选择 1.0000
do-nothing（不学）           Spearman 0.0000 · 成对排序率 0.5000 · top1 0.0833 · 选择 0.5001
random_w（随机权重）         Spearman 0.0455 · 成对排序率 0.5227 · top1 0.0500 · 选择 0.5238
```

⇒ 指标有**工作区间**（不是恒真判据）：正对照能满分、负对照落在机会水平。

### 3.4 接线演示：①层满分 ≠ ②层变好

```
  配置                                    Recall@1  Recall@5       MRR
  (a) 基线：sim                              0.2300    0.2900    0.2889
  (b) 学到但没接线：sim + 0.0·conf               0.2300    0.2900    0.2889   ← 与 (a) 逐位相同
  (c) 接线：sim + 1.0·conf                   0.2350    0.5150    0.3837
  (d) 反号对照：sim + 1.0·随机权重                 0.0500    0.1800    0.1357
```

- **(a)≡(b) 逐位相同是 λ=0 构造出来的 ⇒ 同义反复**，只能当"接线完整性检验"，不能当发现。
- **真发现是 (c)/(d) 两个方向**：②层能分辨接线方向（(c) 全面不劣于且至少一项更好；(d) 全面更差）
  ⇒ **①层满分不蕴含②层变好** ⇒ 把「学到的排序」当「检索质量」报 = **同义改写**。
- ⚠️ 本演示的构造成分：相关集由真值强度导出 ⇒ 它**不证明**机制能提升真实检索；
  且 conf **与查询无关** ⇒ 它只能当全局先验（附录里 (c) 的 Recall@1 只从 0.2300 到 0.2350，
  而 Recall@5/MRR 明显动 —— 这个形态差异本身就是"别用一个指标代表整层"的例子）。

## 4. 表态：H1 / H2 我支持还是反对

### H2 —— **反对**

**理由（全部可复跑）**：

1. H2 的证伪条件**是它自己写的**（`NOTES.md` §3.2：「⚠️ 若纯频次组也学得动 ⇒ H2 被证伪」）——
   实测**触发了**：`freq_passive` = 0.9924（Δ +0.4924，无任何反馈）。
2. 它把三种信号并成两个词，而**这三种的答案不一致**：外部日记频次 0.9924 / 自己选择的计数 0.4773 /
   纯奖励 1.0000 ⇒ **该表述无论结果如何都能自圆**，属于可证伪性不足。
3. 「必须显式偏好信号」不成立：三种**不用标签**的更新都学得动。
4. 且这不是难度问题：k=2/3/5/12 全扫都学得动。
5. 机制也被定位了：**「自己选了谁」+「标量对错」⇒ 方向信息**（错 ⇒ 降被选中的那个）。

**它的真身（我建议改成的表述）**：
> 不是"纯奖励信号不含方向"，而是**「读出形态」决定它能不能被用上** ——
> 固定正基线 + 单位封顶的读出会让"只降不升"锁死；共享一维、无正基线的读出不会。

### H1 —— **部分支持**

- ✅ **发动机（`+1` 加强该选的那位）迁移成立**：`label_boost_err` = 1.0000，且 k 全扫稳（0.99+）。
- ❌ **守门人（稳态/零和）在本层的可测收益 = 0**：0.9958 vs 1.0000（+0.0042），
  且零和的"漂移 0"是**构造性同义反复**。
- ⚠️ **封顶有代价、没测到收益**：0.8409 < 1.0000。
- ⇒ H1 要成立，得先补一句**它到底作用在哪一层**：本线的①②层指标都对绝对水平不敏感。
