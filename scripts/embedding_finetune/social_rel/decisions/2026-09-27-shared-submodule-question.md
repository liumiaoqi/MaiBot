## 一、问题（lmq 2026-09-27 两问）

1. **"share 现在能做成标准子模块了吗？"**
2. **"私有仓库别人应该拉不下吧？"**

## 二、先说第 2 问（✅ 结论明确）

**对，拉不下** ✓ —— 私有仓需要授权 ✓。但要分清**两层**：

| 别人 clone 时 | 会发生什么 |
|---|---|
| 只 clone 父仓（默认） | ⚠️ **不报错** —— `.shared` 只被建成一个**空目录**；**1282 个文件静默消失**、零提示（WB 原决策 §五 就记着这条风险 ✓）|
| clone 后 `git submodule update --init`（**只有在有 `.gitmodules` 时才会发生**）| ✅ **会明确报认证失败** ⇒ 至少**不是静默** ✓ |

⇒ ⭐ 所以"转成标准子模块"**反而会改善**这条风险（从"静默空目录"变成"明确报错"）✓

## 三、再说第 1 问：**技术上能，但不是"改一行配置"**

WB 2026-09-24 否掉转子的四条理由，**今天逐条复核**：

| # | 09-24 的理由 | 2026-09-27 状态 |
|---|---|---|
| 1 | ⚠️ **规范子模块必须有可达 URL，它没有** | ⭐ **这一条已经不成立** —— 现在有 `https://github.com/liumiaoqi/maibot-share.git` ✓✓ |
| 1′ | ⚠️ 它还**住在父仓工作区内部**（`.shared/.git` 是目录 ⇒ 内嵌仓）⇒ 要转，**得把裸仓/内嵌形态处理掉**，**那是搬家不是改配置** | ⚠️ **仍成立** —— 转换要**重建那一个目录**（见 §四）|
| 2 | 转了也不解决痛点（真子模块**同样要 bump 指针**）| ⚠️ **仍成立**（bump 惯例照旧）|
| 3 | `.shared` **已定瘦身** ⇒ 先动结构 = 给即将搬走的东西白干 | ⚠️ **仍成立**（除非瘦身已取消/已完成）|
| 4 | 收益场景不成立（**同机多智能体**共用 ⇒ "别人 clone 能 init" 的价值 ≈ 0）| ⚠️ **仍成立** —— ⭐ 但 **"寒假正式重启"会改变这个前提**（重启后可能不再是单机单路径？）|

## 四、转换要做的事（**准确步骤，共 4 步**）

```bash
cd E:/Users/lmq/MaiBot
# 0) 前置：确认 .shared 已推到远程且零差（今天已满足 ✓）
git -C .shared remote -v && git -C .shared rev-list --count origin/main..HEAD   # 应为 0
# 1) 把内嵌仓从父仓 index 里摘掉（父仓**只丢指针记录**，工作区文件不动）
git rm --cached .shared
# 2) 处理内嵌形态：把 .shared/.git 目录移走（或整目录重建）
mv .shared/.git ../shared-git-backup-$(date +%s)      # 就地备份，可回退
# 3) 以真子模块的方式重新挂上（会写 .gitmodules）
git submodule add https://github.com/liumiaoqi/maibot-share.git .shared
# 4) 提交父仓（会新增 .gitmodules + gitlink 条目）
git add .gitmodules .shared && git commit -m "chore: .shared 转为标准子模块"
```
⚠️ **风险与代价**：
- 第 2 步会**重建 `.shared` 目录** ⇒ 必须**先确认远程零差**（否则丢本地改动 ✓ 今天已满足 ✓）
- 转换后**仍然要 bump 指针**（理由 2 ✓）⇒ **不会**让 `git status` 更干净 ✗
- ⚠️ **所有协作方（CA / CC / CX / WB / dsh）的现有路径假设不变**（还是 `MaiBot/.shared` ✓）✓
